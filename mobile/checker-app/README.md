# Hotel CRM — Checker app

The Expo (React Native) app for the CHECKER role: the attendance queue, quality
inspections and rework, absences, and the checker's own onboarding/HR screens.

Sibling app: `../worker-app` (WORKER role). The two share a backend and a good
deal of ported code, but they are separate apps with distinct bundle IDs
(`com.hotelcrm.checkerapp`), URL schemes (`checkerapp`), push topics, and — see
below — dev-server ports. Only the roles in `ALLOWED_ROLES`
(`src/constants/app-config.ts`) can hold a session here; the gate is enforced in
`src/stores/auth-store.ts`.

## Get started

1. Install dependencies

   ```bash
   npm install
   ```

2. Start the app

   ```bash
   npm start
   ```

   Use `npm start` / `npm run ios` / `npm run android` rather than `npx expo start`
   directly — see "Dev server port" below.

## Dev server port

**This app's dev server is port 8082.** worker-app keeps Expo's default 8081.
Do not set this app to 8081.

Both apps are Expo projects in the same repo and both default to 8081. A checker
build that resolves to 8081 attaches to *worker-app's* Metro and runs the other
app's JavaScript — the apps look alike enough that this reads as a checker-app
bug. It has been reported twice from real iOS builds.

The port is set in three places because there are three ways to start this app,
and each bypasses the others:

| Where | Covers | Mechanism |
|---|---|---|
| `package.json` scripts | `npm start`, `npm run ios` | `--port 8082` |
| `.env` (committed) | `npx expo start` / `run:ios` / `prebuild` run directly | `RCT_METRO_PORT=8082`; every CLI entry point calls `loadEnvFiles()` before resolving the port |
| `plugins/with-metro-port.js` | pressing **Run** in Xcode | writes `export RCT_METRO_PORT=8082` into `ios/.xcode.env` on each prebuild |

The Xcode one is the subtle one: `RCTBundleURLProvider.mm` compiles the default
port in as a constant (`kRCTBundleURLProviderDefaultPort = RCT_METRO_PORT`),
fed by React-Core.podspec's `GCC_PREPROCESSOR_DEFINITIONS`, which resolves from
the build environment. `expo run:ios` sets that environment itself; Xcode takes
it from `ios/.xcode.env`. Since `ios/` is gitignored and regenerated by
`expo prebuild`, the line has to be re-applied on every prebuild — hence the
plugin. `src/__tests__/dev-server-port.test.ts` guards all three.

After changing any of them, re-run `npx expo prebuild --clean` so the native
project picks up the new port.
